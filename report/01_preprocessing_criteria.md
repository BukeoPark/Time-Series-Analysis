# 전처리 기준: 일별 순매출 시계열

- 목적: 일 단위 매출 흐름 분석 및 매출 예측(지수평활 계열)
- 입력: `data/raw/Online Retail.xlsx` (시트 `Online Retail`, 541,909행 × 8열) — 원본은 수정하지 않는다.
- 산출물
  - 전처리 스크립트: `analysis/01_preprocess.py`
  - 정제된 행 단위 자료: `data/processed/transactions_clean.csv`
  - 일별 시계열: `data/processed/daily_sales.csv`
  - 단계별 제외/대체 건수 기록: `outputs/tables/preprocess_log.csv`
- 모든 단계는 아래 순서대로 수행하며, 각 단계의 **적용 전 행 수, 제외 행 수, 제외 행의 Sales 합계**를 `preprocess_log.csv`에 기록한다.

---

## 0. 불러오기와 자료형 정리

| 열 | 처리 | 이유 |
|---|---|---|
| `InvoiceNo` | `str`로 변환, 앞뒤 공백 제거 | int와 str이 섞여 있음 (int 532,618 / str 9,291) |
| `StockCode` | `str`로 변환, 앞뒤 공백 제거 | int와 str이 섞여 있음 |
| `Description` | 앞뒤 공백 제거, 결측은 그대로 둠 | 필터 판단에 사용하지 않음 |
| `Quantity` | `int64` 유지 | |
| `UnitPrice` | `float64` 유지 | |
| `InvoiceDate` | `datetime64` 유지 (시간대 변환 없음, 기록된 현지 시각 그대로) | |
| `CustomerID` | 결측 유지, 필요 시 문자열 식별자로만 사용 | 수치 특징으로 쓰지 않음 |
| `Country` | `str` 유지 | |

파생 열:

```
Sales      = Quantity × UnitPrice          (float64, 반올림하지 않음)
IsCancel   = InvoiceNo가 'C'로 시작하면 True
Date       = InvoiceDate.normalize()       (시각을 버린 날짜)
```

## 1. 완전 중복 행 제거

- 조건: 원본 8개 열(`InvoiceNo`~`Country`)이 모두 같은 행
- 처리: 첫 번째 행만 남기고 나머지 제거 (`drop_duplicates(keep='first')`)
- 원본 기준 대상: 5,268행
- 참고: 동일 송장에 같은 상품을 두 번 입력한 실제 거래일 가능성도 있다. 민감도 확인을 위해 제거 전후 일별 매출 합계 차이를 로그에 함께 기록한다.

## 2. 부실채권 조정 송장 제외

- 조건: `InvoiceNo`가 `'A'`로 시작 (StockCode `B`, "Adjust bad debt")
- 처리: 제거
- 원본 기준 대상: 3행

## 3. 단가 0 이하 행 제외

- 조건: `UnitPrice <= 0`
- 처리: 제거
- 원본 기준 대상: 단가 0 2,515행, 단가 음수 2행 (2단계와 겹칠 수 있음)
- 이유: 판매 금액이 발생하지 않는 기록(재고 조정, 상품명 결측 등)

## 4. 취소가 아닌 음수 수량 행 제외

- 조건: `IsCancel == False` 이고 `Quantity < 0`
- 처리: 제거
- 원본 기준 대상: 1,336행 (모두 단가 0이므로 3단계에서 먼저 제거됨. 안전장치로 조건을 유지함)
- 이유: 재고 조정 기록이며 매출이 아님

## 5. 비상품·회계 코드 제외

`StockCode`가 아래 목록에 해당하면 제거한다. 대소문자는 구분하지 않고, `gift_0001_`로 시작하는 코드도 포함한다.

| StockCode | 의미 | 원본 행 수 | 제외 이유 |
|---|---|--:|---|
| `POST` | 배송비 | 1,256 | 상품 매출 아님 |
| `DOT` | 온라인 배송비 | 710 | 상품 매출 아님 |
| `C2` | 운송비 | 144 | 상품 매출 아님 |
| `M`, `m` | 수동 입력 | 572 | 내용 불명확, 큰 금액 조정 포함 |
| `D` | 할인 | 77 | 회계 조정 |
| `S` | 샘플 | 63 | 회계 조정 |
| `BANK CHARGES` | 은행 수수료 | 37 | 회계 조정 |
| `AMAZONFEE` | 아마존 수수료 | 34 | 회계 조정, 건당 최대 약 £17,836 |
| `CRUK` | 기부 수수료 | 16 | 회계 조정 |
| `B` | 부실채권 조정 | 3 | 2단계에서 제거됨 |
| `gift_0001_*` | 상품권 판매 | 34 | 선불 결제이며 상품 매출 아님 |

- `DCGS*`(온라인 판매 상품), `PADS`는 실제 상품이므로 **유지**한다.
- 이 단계에서 취소 송장(`C`)의 행도 같은 코드 기준으로 함께 제거한다.

## 6. 취소 행 처리

- 취소 행(`IsCancel == True`)은 **제거하지 않는다.** 음수 `Sales`인 채로 순매출 계산에 포함한다.
- 취소는 원 주문 날짜가 아니라 **취소 송장의 `InvoiceDate` 날짜**에 반영한다. 원 주문을 소급해 수정하면 예측 시점 이후 정보가 과거 값에 섞이기 때문이다.
- 결과: 대량 주문 뒤 즉시 취소된 건(£168,469.60, £77,183.60)은 주문과 취소가 같은 날이므로 일별 순매출에서 상쇄된다.
- 2010-12-01 이전 주문에 대한 취소는 원 주문이 없어도 그대로 음수로 반영한다.

## 7. CustomerID 결측

- 처리하지 않는다. 행을 유지하고 대체하지도 않는다.
- 이유: 결측 행도 실제 판매이며(원본의 24.9%), 매출 총량 분석에 필요하다.

→ 1~7단계를 거친 결과를 `data/processed/transactions_clean.csv`로 저장한다.

## 8. 일별 집계

```
daily_gross   = Date별 Sales 합계 (IsCancel == False 행)
daily_cancel  = Date별 Sales 합계 (IsCancel == True 행, 음수)
daily_net     = daily_gross + daily_cancel
n_invoices    = Date별 고유 InvoiceNo 수 (취소 제외)
```

- 예측 대상 변수는 `daily_net`(순매출, 단위: 파운드 £)이다.

## 9. 영업일 달력 구성

1. **기간:** 2010-12-01 ~ 2011-12-08
   - 2011-12-09는 12:50까지만 기록되어 하루치가 아니므로 제외한다.
2. **토요일 제거:** 전체 기간에 토요일 거래가 한 건도 없으므로 휴무 요일로 보고 달력에서 뺀다. 일~금 6일을 1주로 하는 영업일 달력을 만든다.
3. **빈 영업일 채우기:** 영업일인데 거래가 없는 날은 `daily_gross`, `daily_cancel`, `daily_net`, `n_invoices`를 0으로 채우고 `is_closed = 1`로 표시한다.
   - 원본 기준 해당일(토요일 제외 16일): 2010-12-24, 12-26~12-31, 2011-01-02, 01-03, 04-22, 04-24, 04-25, 04-29, 05-02, 05-30, 08-29

## 10. 모델 입력 시계열 (`sales_model`)

`daily_net`은 관측값 그대로 보존하고, 모델 입력용 열 `sales_model`을 따로 만든다.

1. **시작일 조정:** 모델 학습은 **2011-01-04부터** 사용한다. 연말연시 연속 휴무(2010-12-24~2011-01-03)가 계절 패턴 초기값을 왜곡하기 때문이다. 2010-12-01~12-23 구간은 탐색적 분석에서만 사용한다.
2. **휴무일 대체:** 2011-01-04 이후 `is_closed == 1`인 날의 `sales_model`은 **6영업일 전(같은 요일) 값**으로 대체한다.
   - 과거 값만 사용하므로 예측 시점 이후 정보가 들어가지 않는다.
   - 6영업일 전도 휴무이면 그보다 6영업일 더 앞의 값을 쓴다.
   - 대체한 날짜와 원래 값(0)과 대체 값을 `preprocess_log.csv`에 기록한다.
   - 예측 성능 평가에서는 대체한 날을 제외하고 오차를 계산한다.
3. **양수 확인:** `sales_model <= 0`인 날의 수를 기록한다.
   - 1일 이상 있으면 가법(additive) 모형만 사용한다.
   - 없으면 곱셈(multiplicative) 계절성과 로그 변환도 후보로 비교한다.

## 11. 학습/검증 분할

- 시간 순서대로 나누고, 섞지 않는다.
- **검증 구간:** 마지막 24영업일(4주 = 6영업일 × 4), 2011-12-08까지
- **학습 구간:** 2011-01-04부터 검증 시작 전날까지
- 계절 주기: `seasonal_periods = 6` (영업일 기준 1주)
- 평가 지표: MAE, RMSE, MAPE(검증 구간에 0에 가까운 값이 있으면 MAPE는 참고용)
- 기준 모델: 계절 나이브(6영업일 전 값)와 비교한다.

## 12. 정밀도와 표시

- 모든 계산은 `float64`로 하고, 중간 단계에서 반올림하지 않는다.
- 소수점 2자리 반올림은 표와 그래프를 **보여줄 때만** 적용한다.

## 13. `daily_sales.csv` 열 정의

| 열 | 자료형 | 설명 |
|---|---|---|
